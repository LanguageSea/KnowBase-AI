# KnowBase AI Platform 企业级升级总控要求

## 一、项目背景

现有项目采用 Vue 3 + Spring Boot + FastAPI + MySQL + Redis + Qdrant，已有知识库管理、文档处理、RAG 问答、模型配置、权限及部署相关功能。具体完成情况必须以仓库代码、数据库迁移文件和实际运行结果为准。

目标是将项目逐步升级为企业 AI 应用开发与运行平台，增加组织与租户治理、模型网关、配额管理、应用版本、工作流执行、工具中心、数据连接器、AI 评测、可观测性、安全策略和生产运维能力。

## 二、实施前必须完成的工作

1. 检查前后端目录、模块依赖、现有 API、数据库表、迁移脚本、任务机制、权限实现和部署配置。
2. 为每个计划功能标记：已实现、部分实现、未实现、需要重构。
3. 识别现有实现可以复用的类、表、接口和组件。
4. 不得未经分析重建用户、知识库、文档、模型、任务、审计等已有功能。
5. 输出当前架构图、模块依赖图、现有表清单、风险清单和增量迁移方案。

## 三、架构约束

1. 继续使用 Vue 3、Spring Boot、FastAPI、MySQL、Redis、Qdrant。
2. 优先采用模块化单体承载 Java 平台业务，Python 作为独立 AI Runtime。
3. 不得为了展示技术而强行引入微服务、Kafka、Kubernetes 或图数据库。
4. 所有跨服务调用必须定义超时、错误语义、认证和可观测性。
5. 所有关键配置、应用版本和工作流定义必须具备版本化机制。
6. 后台任务必须具备明确状态机、幂等策略、失败处理和恢复机制。
7. 所有资源访问必须执行服务端授权，覆盖异步任务、缓存、文件、向量检索和工具调用。
8. 生产密钥不得进入前端代码、Git、普通日志或明文数据库字段。

## 四、开发优先顺序

第一阶段：身份与资源授权、密钥管理、任务可靠性、全链路观测、自动化测试和数据库迁移。

第二阶段：模型网关、配额与成本、应用注册与版本、工具中心。

第三阶段：工作流执行引擎、AI 评测、数据连接器、灰度发布和安全策略。

第四阶段：Agent、多模态、数据血缘、插件市场、高级调度和高可用部署。

## 五、每个模块必须提交的成果

1. 业务需求与边界说明。
2. 架构设计和技术选型理由。
3. 数据库迁移脚本及回滚/恢复说明。
4. API 契约、参数校验、错误码和权限要求。
5. 前端页面与真实交互。
6. 核心实现代码、单元测试和集成测试。
7. 日志、指标、Trace 和安全审计。
8. Docker 部署配置和环境变量模板。
9. 验收脚本、测试结果和故障排查文档。
10. 对现有功能的回归测试结果。

## 六、开发纪律

- 一次只实现一个可验收的垂直切片，不要一次生成所有模块。
- 编码前先给出实现计划、涉及文件、数据库变化、API 变化和风险。
- 不得删除或重命名现有字段，除非先提出兼容迁移方案并得到确认。
- 不得使用假数据冒充真实运行结果，不得虚构测试、性能或安全指标。
- 不得仅新增菜单或空接口就声称功能完成。
- 每个阶段必须运行实际测试并报告通过、失败、未执行的项目。
- 发现现有架构问题时，先说明原因、影响范围和最小修复方案。
- 完成后更新架构文档、接口文档、数据库文档和部署手册。

## 七、首个交付任务

本轮只进行仓库审计和总体设计，不批量修改业务代码。

请输出：
1. 现有功能与计划功能的差异矩阵。
2. 当前架构和模块边界。
3. P0、P1、P2 功能的依赖关系。
4. 现有数据库表的复用和扩展方案。
5. 第一阶段详细开发计划。
6. 第一阶段的测试与验收标准。

等待审查通过后，再逐模块实现。
