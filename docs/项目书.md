# 第一章：项目概述

## 1.1 项目背景

企业内部通常积累了大量技术文档、业务制度、产品手册、培训资料和操作规范。这些资料分散在不同文件夹或业务系统中，员工查找信息需要花费较多时间。

传统关键词搜索难以准确理解自然语言问题，而直接使用通用大模型又可能出现回答缺乏企业资料依据、内容不准确或泄露内部信息等问题。

知库 AI 旨在建立一个统一的企业知识管理平台，通过文档数字化处理、语义检索、检索增强生成（RAG）和权限控制，让员工能够基于有权访问的内部资料进行自然语言问答。

## 1.2 项目建设目标

1. 建立统一的企业知识库，实现文档集中管理。
2. 支持多格式文档上传、解析、切分、索引和更新。
3. 实现基于企业内部知识的 AI 智能问答。
4. 回答时提供可追溯的文档来源和引用片段。
5. 建立用户、角色、知识库成员等多层级权限体系。
6. 支持多个大模型服务商的配置与切换。
7. 建立任务状态、调用记录、异常日志和操作审计机制。
8. 支持 Docker 部署，提供完整的安装文档、接口文档和测试用例。

## 1.3 项目范围

本项目第一版聚焦于企业知识管理与智能问答，不涉及模型训练、复杂工作流编排和商业化计费。

| 范围类别    | 具体内容                                           |
| ----------- | -------------------------------------------------- |
| 用户端      | 登录、知识库访问、文档浏览、AI 对话、历史记录      |
| 管理端      | 用户管理、角色管理、知识库管理、模型配置、运行监控 |
| Java 服务   | 业务接口、身份认证、权限控制、任务管理、会话持久化 |
| Python 服务 | 文档解析、文本切分、向量生成、检索、模型调用       |
| 数据层      | MySQL、Redis、Qdrant、文件存储                     |
| 工程化      | 自动化测试、日志、异常处理、Docker 部署            |

# 第二章：用户角色与权限体系

系统采用基于角色的访问控制（RBAC），并在知识库层增加资源级权限控制。

## 2.1 用户角色

角色一：系统管理员

负责用户账户、角色权限、模型服务配置、系统参数、运行日志和审计记录。

角色二：知识库管理员

负责自己有权管理的知识库、文档上传与删除、成员授权、文档处理任务及知识质量维护。

角色三：普通用户

访问已授权的知识库，查看允许访问的文档，进行 AI 问答和管理个人会话。

## 2.2 权限分类

| 权限类别           | 系统管理员 | 知识库管理员       | 普通用户   |
| ------------------ | ---------- | ------------------ | ---------- |
| 登录、修改个人资料 | 是         | 是                 | 是         |
| 用户与角色管理     | 是         | 否                 | 否         |
| 创建知识库         | 是         | 按授权策略         | 否         |
| 管理知识库成员     | 是         | 自有或获授权知识库 | 否         |
| 上传、更新文档     | 是         | 有管理权限时       | 按授权策略 |
| 删除文档           | 是         | 有管理权限时       | 否         |
| AI 问答            | 是         | 是                 | 是         |
| 查看个人会话       | 是         | 是                 | 是         |
| 查看他人会话       | 按审计授权 | 默认否             | 否         |
| 配置模型服务       | 是         | 否                 | 否         |
| 查看系统审计日志   | 是         | 仅限授权范围       | 否         |

权限应以服务端校验结果为准。系统管理员不应默认绕过所有数据访问审计，敏感操作仍须记录。

# 第四章：各功能模块详细需求

## 4.1 用户与身份管理模块

### 4.1.1 登录认证

功能包括：

- 用户名和密码登录。
- 登录表单校验。
- 登录失败提示及失败次数限制。
- 退出登录。
- 登录状态校验。
- 未登录访问受保护页面时跳转登录页。
- 登录成功后根据权限加载菜单。
- 密码修改及密码强度校验。

### 4.1.2 用户账户管理

管理员可以：

- 创建用户。
- 编辑用户基本信息。
- 启用或禁用账户。
- 重置用户密码。
- 分配系统角色。
- 按用户名、状态、角色筛选用户。
- 查看用户创建时间、最近登录时间。

### 4.1.3 角色与菜单权限

- 创建、修改和停用角色。
- 为角色分配菜单和操作权限。
- 为角色分配后端 API 权限。
- 管理用户与角色的关联。
- 对越权请求返回统一的权限错误。
- 记录关键权限变更。

### 4.1.4 个人中心

- 查看个人资料。
- 修改昵称和允许修改的个人信息。
- 修改密码。
- 查看自己的登录记录。
- 查看自己的问答历史。
- 配置个人默认知识库或偏好设置。

第一版验收： 用户可以登录、退出、修改密码；管理员能管理账户；普通用户不能调用管理员接口。

## 4.2 工作台与首页模块

首页根据用户角色展示不同内容。

### 4.2.1 普通用户工作台

- 最近访问的知识库。
- 最近问答会话。
- 常用知识库快捷入口。
- 快速发起提问。
- 文档检索入口。
- 最近操作记录。

### 4.2.2 管理员工作台

- 用户总数与启用用户数。
- 知识库总数。
- 文档总数和处理失败数。
- 今日问答次数。
- AI 调用失败数量。
- 文档处理任务状态分布。
- 系统服务健康状态。

### 4.2.3 数据统计规则

所有统计数据必须来自真实业务数据，不允许使用固定数字伪装实时运行状态。

统计接口应明确时间范围、统计口径和当前用户的数据可见范围。

## 4.3 知识库管理模块

### 4.3.1 知识库创建

创建知识库时填写：

- 知识库名称。
- 知识库描述。
- 分类或标签。
- 可见范围。
- 默认检索配置。
- 是否启用。
- 管理员或负责人。

### 4.3.2 知识库列表

支持：

- 分页查询。
- 按名称搜索。
- 按分类筛选。
- 按创建人筛选。
- 按状态筛选。
- 按创建时间排序。
- 显示文档数量和成员数量。
- 查看详情、编辑和归档。

### 4.3.3 知识库成员管理

- 添加成员。
- 移除成员。
- 设置成员权限。
- 查看成员列表。
- 查询成员授权记录。
- 防止重复授权。
- 移除成员后立即阻止其继续访问对应知识库。

### 4.3.4 知识库生命周期

- 启用和停用。
- 归档。
- 取消归档。
- 查看知识库统计。
- 删除前检查关联文档、会话及任务。
- 通过可恢复的删除或归档流程清理关联数据。

### 4.3.5 知识库隔离规则

- 用户只能查看自己有权访问的知识库。
- 文档检索必须限制在授权知识库范围内。
- 不得仅凭客户端提交的知识库 ID 判断权限。
- 删除、更新和下载操作必须重新校验权限。

第一版验收： 知识库创建、编辑、成员授权、访问控制均可实际操作，不能出现通过修改 URL 或接口参数越权访问的情况。

## 4.4 文档管理模块

### 4.4.1 文件上传

第一版支持：

- PDF。
- DOCX。
- TXT。
- Markdown。

后续可扩展 DOC、PPTX、XLSX、HTML 等格式。

上传要求：

- 校验文件扩展名和实际文件类型。
- 限制文件大小。
- 生成唯一存储标识。
- 避免使用用户提供的文件名直接构造物理路径。
- 记录上传人、所属知识库、文件大小和上传时间。
- 上传成功后创建文档处理任务。

### 4.4.2 文档列表

展示以下字段：

| 字段       | 说明                         |
| ---------- | ---------------------------- |
| 文档名称   | 原始名称或展示名称           |
| 所属知识库 | 文档所属知识库               |
| 文件类型   | PDF、DOCX 等                 |
| 文件大小   | 文件大小                     |
| 上传人     | 文档上传者                   |
| 上传时间   | 上传时间                     |
| 处理状态   | 待处理、处理中、成功、失败等 |
| 分片数量   | 已建立的文本分片数量         |
| 操作       | 详情、重试、下载、删除       |

### 4.4.3 文档详情

- 文件基本信息。
- 处理状态及错误摘要。
- 处理任务历史。
- 文档分片预览。
- 索引建立时间。
- 当前文档版本。
- 重新处理操作。
- 下载原始文件（仅对有权用户开放）。

### 4.4.4 文档更新与删除

- 支持替换文档或上传新版本。
- 新版本完成索引后再切换有效版本。
- 处理失败时保留必要的旧版本数据，避免直接导致知识库不可用。
- 删除时清理文件、文档元数据、文本分片和向量索引。
- 清理失败时保留任务记录并支持重试。
- 对正在执行的处理任务进行冲突控制。

### 4.4.5 文档去重

- 对文件计算哈希值。
- 检查同一知识库中是否存在重复文件。
- 支持提示重复上传。
- 不应在不同权限范围内无条件暴露文件是否存在。

## 4.5 文档处理引擎模块

这是 Java 与 Python 协作的关键模块。

### 4.5.1 任务创建与调度

- 上传文档后创建处理任务。
- 记录任务类型、状态和创建时间。
- 支持排队、开始、成功、失败和取消等状态。
- 防止同一文档被重复并发处理。
- 支持失败重试。
- 限制重试次数。
- 记录每次执行的错误摘要。

### 4.5.2 文档解析

Python 服务负责：

- 识别文件类型。
- 提取文本内容。
- 保留适当的段落与标题结构。
- 处理空文件和无法解析的文件。
- 记录解析失败原因。
- 对超大文件进行大小与处理时间限制。

### 4.5.3 文本清洗与切分

- 去除无意义空白。
- 处理重复换行。
- 尽可能保留标题、段落和列表关系。
- 根据配置的长度进行切分。
- 支持分块重叠。
- 记录分片顺序和来源页码等可用元数据。
- 避免产生大量空分片。

### 4.5.4 向量生成

- 根据配置调用 Embedding 模型。
- 校验返回向量维度。
- 批量处理分片。
- 控制请求大小和并发量。
- 对失败批次进行有限重试。
- 记录模型名称、向量维度和处理时间。

### 4.5.5 向量索引管理

- 创建或使用对应的 Qdrant 集合。
- 写入分片向量及必要的过滤元数据。
- 关联知识库、文档、版本和分片 ID。
- 支持文档更新后的旧索引清理。
- 支持索引状态检查。
- 支持索引重建。
- 避免重复任务生成重复有效索引。

### 4.5.6 处理结果反馈

处理结束后更新：

- 文档处理状态。
- 任务执行结果。
- 成功分片数量。
- 失败原因。
- 任务耗时。
- 最后一次处理时间。

第一版验收： 上传一个支持的文档后，能够查看处理状态、预览文本分片，并在 Qdrant 中检索到其内容。

## 4.6 AI 智能问答模块

### 4.6.1 问答入口

- 无需预先选择知识库，自动检索当前用户全部可读知识库。
- 输入自然语言问题。
- 提交问题。
- 停止正在生成的回答。
- 创建新会话。
- 展示回答加载状态。
- 模型完整生成后，以打字机效果逐步渲染回答。
- 处理空问题和过长问题。

### 4.6.2 检索流程

- 对用户问题进行必要的规范化处理。
- 生成查询向量。
- 在有权访问的知识库范围内检索。
- 根据相似度阈值筛选结果。
- 支持配置 Top-K。
- 返回相关文本片段及来源元数据。
- 无匹配结果时给出合理提示。

### 4.6.3 上下文构建

- 控制传入模型的上下文长度。
- 去除重复片段。
- 合并必要的来源信息。
- 采用明确的系统提示词。
- 明确区分用户问题、检索资料和模型指令。
- 将检索资料视为待分析的数据，不能执行资料中隐藏的指令。

### 4.6.4 大模型回答

- 根据检索上下文生成答案。
- 支持流式输出。
- 前端先接收完整生成结果，再以打字机效果渲染文字。
- 支持超时和取消。
- 记录调用耗时和可获得的 Token 用量。
- 处理服务商限流、鉴权失败和网络异常。
- 在没有足够证据时先明确提示“知识库中未找到相关依据”，再提供标注为通用知识、
  不含引用的回答；不得把通用知识表述为企业内部事实。

### 4.6.5 引用来源

每条回答可以关联：

- 来源文档名称。
- 文档 ID。
- 分片 ID。
- 页码或章节信息（如果可用）。
- 引用的原文片段。
- 文档预览或定位入口。

引用必须对应真实检索到的资料，不能由模型随意编造文档名或页码。

### 4.6.6 用户反馈

- 对回答进行有帮助或无帮助评价。
- 可选填写反馈原因。
- 记录问题、回答和引用之间的关联。
- 为后续检索效果评估提供数据。

### 4.6.7 问答安全

- 用户只能检索有权访问的知识库。
- 限制单次请求长度和频率。
- 对模型调用设置超时。
- 不向普通用户返回服务商密钥、内部异常堆栈等敏感信息。
- 防止跨知识库信息泄露。

第一版验收： 用户提问后能够得到基于实际文档的回答，展示真实引用；无依据时有明确提示；无权访问的资料不能进入检索上下文。

## 4.7 会话管理模块

### 4.7.1 会话操作

- 创建会话。
- 自动生成或手动修改会话标题。
- 查看会话列表。
- 按时间排序。
- 查看历史消息。
- 删除个人会话。
- 继续历史对话。
- 在会话中查看每次回答的引用来源。

### 4.7.2 消息管理

每条消息记录：

- 会话 ID。
- 消息角色。
- 消息内容。
- 创建时间。
- 请求状态。
- 模型信息。
- 响应耗时。
- 可用的 Token 用量。
- 引用来源关联。

### 4.7.3 上下文与历史消息

- 仅在需要时加载历史上下文。
- 控制历史消息长度。
- 防止将其他会话内容混入当前请求。
- 删除会话时按既定策略清理关联数据。
- 对正在生成的回答处理好取消和保存状态。

## 4.8 模型服务管理模块

### 4.8.1 服务商配置

- 新增模型服务商。
- 配置 API Base URL。
- 配置模型名称。
- 配置 API Key。
- 启用或禁用配置。
- 编辑和删除配置。
- 测试连接。
- 查看最近一次连接状态。

### 4.8.2 模型类型

需要区分以下模型能力：

| 模型类型         | 作用                   |
| ---------------- | ---------------------- |
| Chat / LLM       | 生成问答内容           |
| Embedding        | 将文本转换为向量       |
| Reranker（可选） | 对检索结果进行二次排序 |

模型配置不能只记录模型名称，还应记录服务商、模型类型、接口地址和必要的兼容参数。

### 4.8.3 调用统计

- 调用次数。
- 成功次数与失败次数。
- 平均响应耗时。
- 可获得的 Token 用量。
- 服务商和模型维度统计。
- 错误类型统计。

### 4.8.4 密钥保护

- 密钥加密存储。
- 页面只显示脱敏结果。
- 修改密钥时不回显原文。
- 日志不记录完整密钥。
- 删除配置前检查关联任务。
- 生产环境优先使用环境变量或受控密钥管理方式。

## 4.9 检索与知识质量管理模块

此模块是提升项目技术含量的重要组成部分。

### 4.9.1 检索参数配置

- Top-K。
- 相似度阈值。
- 分片长度。
- 分片重叠长度。
- 是否启用 Reranker。
- 检索超时时间。
- 上下文长度限制。

参数变更后应进行基本校验，并明确配置的适用范围。

### 4.9.2 检索调试工具

管理员可以输入测试问题，查看：

- 检索到的文档。
- 分片内容。
- 相似度分数。
- 排序结果。
- 使用的检索参数。
- 是否命中预期文档。

### 4.9.3 RAG 评估

建立固定测试集，至少覆盖：

- 可以从文档中直接回答的问题。
- 需要综合多个段落的问题。
- 知识库中没有答案的问题。
- 容易检索到相似但错误资料的问题。
- 不同知识库之间的权限隔离问题。

统计指标可以包括：

- 检索命中率。
- Recall@K。
- 引用正确性。
- 回答相关性。
- 无依据回答比例。
- 响应耗时。

指标必须有明确的计算规则，不能把模型自评结果直接当成客观准确率。

## 4.10 系统管理与审计模块

### 4.10.1 操作日志

记录以下关键操作：

- 登录和退出。
- 用户创建、禁用和角色变更。
- 知识库创建、删除和权限修改。
- 文档上传、更新和删除。
- 模型配置变更。
- 敏感操作的执行结果。

日志至少包括操作者、操作类型、目标资源、时间和结果。

### 4.10.2 运行日志

- Java 服务错误日志。
- Python AI 服务错误日志。
- 文档处理任务错误日志。
- 模型调用失败日志。
- 外部依赖异常。
- 请求关联 ID，便于跨服务追踪。

### 4.10.3 服务监控

- Java 服务健康状态。
- Python 服务健康状态。
- MySQL 连接状态。
- Redis 连接状态。
- Qdrant 连接状态。
- 文档任务积压情况。
- 最近错误统计。

健康检查应与实际依赖状态相匹配，不能只因进程启动就显示所有服务正常。

## 4.11 通知与任务中心

### 第一版功能

- 查看本人有权限访问的文档处理任务。
- 展示排队、处理中、成功、失败等状态。
- 查看失败原因。
- 对支持重试的任务发起重试。
- 展示任务开始和结束时间。

### 后续扩展

- 站内通知。
- 邮件通知。
- 长任务实时进度。
- 批量任务管理。
- 任务优先级和并发控制。

第一版可通过轮询任务状态实现，不必一开始就引入消息队列。后续当任务规模和可靠性要求提高时，再评估 RabbitMQ 等组件。

## 4.12 系统安全模块

系统安全是独立的横向能力，不应仅作为一个管理页面。

包括：

1. 密码哈希和登录失败限制。
2. 服务端身份认证及接口授权。
3. 知识库和文档资源级权限控制。
4. 上传文件格式、大小和路径安全检查。
5. 模型密钥加密及日志脱敏。
6. 对模型调用实施频率和资源限制。
7. 防止跨知识库检索和数据泄露。
8. 处理文档内容中的提示词注入风险。
9. 保护内部错误信息，避免向客户端暴露堆栈。
10. 配置 HTTPS、CORS 和生产环境访问控制。
11. 对危险操作实施审计。
12. 为备份文件和敏感配置设置访问权限。

## 6.3 数据设计约束

- 主键统一使用适合业务规模的主键策略。
- 对用户名、成员关联和必要的业务唯一键建立唯一约束。

# 第七章：技术架构与服务边界

## 7.1 服务划分

| 服务        | 职责                               | 不应承担的职责                   |
| ----------- | ---------------------------------- | -------------------------------- |
| Vue 前端    | 页面交互、状态展示、请求发起       | 不直接连接数据库或向量库         |
| Spring Boot | 用户、权限、业务数据、任务编排     | 不承担大量耗时的文档解析         |
| FastAPI     | 文档解析、Embedding、RAG、模型调用 | 不绕过 Java 服务自行决定用户权限 |
| MySQL       | 结构化业务数据                     | 不承担全部向量检索               |
| Redis       | 缓存、限流、短期状态               | 不作为唯一业务持久化存储         |
| Qdrant      | 向量存储和相似度检索               | 不作为用户角色和授权的唯一来源   |
| 文件存储    | 原始文件及必要产物                 | 不代替文档元数据和任务状态管理   |

## 7.2 跨服务接口约定

Java 服务与 Python 服务之间应统一：

- API 版本。
- 请求与响应格式。
- 超时配置。
- 错误码规范。
- 请求关联 ID。
- 鉴权机制。
- 重试策略。
- 日志脱敏规范。

长耗时任务应返回任务 ID，由前端查询任务状态，而不是让一次 HTTP 请求长时间等待完整处理结果。

# 第十一章：风险与解决方案

| 风险                             | 解决方案                                     |
| -------------------------------- | -------------------------------------------- |
| Codex 一次生成过多代码，难以维护 | 先定规范，按模块分阶段开发                   |
| 模型 API 不稳定                  | 设置超时、有限重试和明确错误状态             |
| 文档格式复杂导致解析失败         | 限定第一版格式，建立失败记录和可扩展解析器   |
| AI 回答没有依据                  | 使用引用、固定测试集和无答案处理策略         |
| 知识库权限泄露                   | 在检索前实施服务端授权过滤                   |
| 文档与向量索引不一致             | 建立任务状态、重试和清理机制                 |
| 部署成本过高                     | 先使用本地或单机部署，评估资源后再上云       |
| 需求持续膨胀                     | 以 V1.0 功能清单为边界，扩展需求进入后续版本 |

## 附录 B：交给 Codex 的项目书执行要求

请以《知库 AI 企业知识库与智能问答平台项目书 V1.0》为唯一业务范围基准，协助我从零开发该项目。

### 执行规则

1. 先建立项目需求、系统架构、数据库设计、接口规范、安全规范、开发计划和验收文档。
2. 在编码前核对功能模块之间的依赖关系，并给出可执行的任务清单。
3. 采用 Vue 3 + Spring Boot + Python FastAPI 的前后端分离架构。
4. 第一版采用模块化单体 Java 后端，不引入不必要的微服务。
5. 每个模块都必须具备真实业务逻辑、异常处理和必要测试。
6. 严格执行知识库权限隔离，不允许通过前端控制代替后端授权。
7. 文档处理任务必须有明确状态、错误记录和重试机制。
8. AI 生成的回答必须尽可能提供真实引用来源，不能伪造引用。
9. 所有模型密钥和数据库密码通过安全配置管理，不提交到代码仓库。
10. 每完成一个阶段，更新开发文档、测试结果、已完成事项和待解决问题。
