# 知库 AI 项目技术展示网站开发需求

## 一、项目目标

为「知库 AI（KnowBase AI）」企业级智能知识库与 RAG 问答平台开发一个独立的项目展示网站。

网站主要面向招聘面试官，用于展示项目背景、技术栈、功能模块、系统架构、核心技术实现、测试情况、部署方式和个人贡献。

这不是知识库管理后台，也不是普通个人简历网页，而是一个具有产品官网质感的技术项目展示站。

## 二、开发前要求

1. 先检查现有项目目录、技术栈、README、数据库设计和已实现功能。
2. 以真实代码和文档为依据整理技术栈和功能清单。
3. 不要虚构尚未实现的功能、性能数据、用户数量或测试成绩。
4. 展示网站应与原项目分离，避免影响现有后端和前端。
5. 如果仓库中已有 Vue 3 + Vite 项目，可新建独立展示应用；如果尚无展示站，则优先采用 Vue 3 + TypeScript + Vite。
6. 先完成页面结构、视觉风格和响应式布局，再补充真实项目资料。

## 三、视觉设计

采用专业的深色科技风，使用深海军蓝背景、蓝紫色渐变、适度的网格纹理、清晰的排版和克制的发光效果。

要求：
- 整体具有成熟 SaaS 产品官网的质感。
- 避免大面积无意义的渐变、过多圆角卡片和廉价的 AI 生成式设计。
- PC 端优先，同时适配平板和手机。
- 导航栏支持平滑滚动到对应章节。
- 动效简洁，不影响页面性能和可读性。
- 技术架构图必须清晰，不能只使用装饰性图标代替真实架构关系。

## 四、页面模块

### 1. 首页 Hero 区域
- 项目名称：知库 AI / KnowBase AI。
- 项目定位：企业级智能知识库与 RAG 问答平台。
- 简短项目介绍。
- 技术栈标签。
- 在线体验按钮。
- 查看源码按钮。
- 查看技术架构按钮。
- 明确标注独立开发或本人负责的真实范围。

### 2. 项目背景与目标
- 介绍企业知识分散、文档难检索、通用模型回答缺少依据等问题。
- 展示项目目标和核心解决方案。
- 用简洁的信息图说明业务价值。

### 3. 技术栈展示
按前端、Java 后端、Python AI 服务、数据存储、模型接入、部署运维分类。

每项技术都包含：
- 技术名称。
- 在本项目中的用途。
- 具体应用位置或实现内容。

仅展示实际使用的技术，不添加未经验证的框架。

### 4. 功能模块
根据实际项目实现情况展示：
- 登录认证和权限管理。
- 知识库管理及成员授权。
- 文档上传、解析、分块与索引。
- RAG 智能问答和引用来源。
- 对话记录。
- 模型配置与连接测试。
- 调用日志、操作审计和健康检查。

每个模块应包含功能说明、界面截图或真实 UI 预览、涉及技术及实现原理。

尚未实现的功能不得标注为已完成。

### 5. 系统架构
展示 Vue 3、Nginx、Spring Boot、FastAPI、MySQL、Redis、Qdrant、文件存储及模型 API 之间的真实调用关系。

明确：
- 前端与 Java 后端的请求关系。
- Java 服务与 Python AI 服务的内部调用关系。
- Python 服务与向量数据库、文件及模型 API 的关系。
- 认证授权、任务调度和异常处理的位置。

架构图必须与实际代码一致。

### 6. 核心技术原理
重点展示：
- 文档处理和向量索引流程。
- RAG 检索与上下文组装流程。
- SSE 流式问答流程。
- 知识库权限过滤流程。
- 异步任务失败恢复和重复处理控制。

使用流程图、简短说明和关键代码片段进行展示，避免大段文字堆积。

### 7. 工程质量与安全
展示实际实现的：
- 身份认证与权限控制。
- 文件上传校验。
- 模型密钥保护和日志脱敏。
- 异步任务状态管理。
- 接口异常处理。
- 自动化测试和权限回归测试。
- Docker Compose 部署与备份恢复。

### 8. 测试与项目成果
展示真实测试用例、测试结果和 RAG 评估数据。

如果尚未执行测试，显示待验证状态，不得伪造测试通过率、准确率、响应时间或性能指标。

### 9. 在线演示与源码
提供：
- 在线体验地址。
- 演示账号说明。
- GitHub 或 Gitee 仓库链接。
- README 和部署文档入口。
- 推荐体验问题。
- 演示环境使用限制。

链接通过统一配置管理。未配置的链接隐藏或明确显示待部署状态。

### 10. 个人贡献与面试重点
展示本人实际完成的工作、遇到的技术难点、解决过程及设计取舍。

提供适合面试官阅读的技术说明，但不夸大个人贡献。

## 五、交互要求

- 导航栏定位到页面章节。
- 功能卡片支持查看详细说明。
- 架构节点可点击查看组件职责。
- 核心流程支持逐步展开。
- 代码片段支持复制。
- 演示地址和源码地址通过配置维护。
- 页面在桌面端和移动端均可正常使用。
- 所有按钮都必须有真实行为，不允许保留无功能的装饰按钮。

## 六、代码要求

- 组件化开发。
- TypeScript 类型清晰。
- 统一管理项目介绍、技术栈、功能模块和外部链接。
- 适当拆分页面组件，避免单文件过大。
- 不在前端写入任何模型 API Key、数据库密码或服务器敏感信息。
- 不依赖必须登录才能访问的内部接口展示项目介绍。
- 生产构建通过后再进行部署。

## 七、交付内容

1. 可运行的项目展示网站。
2. 页面组件和样式源码。
3. 项目技术栈及功能资料配置。
4. 本地运行说明。
5. 生产构建及部署说明。
6. 上线前检查清单。
7. 所有未实现功能、未配置链接和待验证指标的清单。

## 八、验收标准

- 页面完整覆盖项目背景、技术栈、功能、架构、核心技术、测试、部署及个人贡献。
- 页面信息与实际代码和项目文档一致。
- 所有导航和交互有效。
- 不存在虚构技术、虚假指标和无效按钮。
- 本地可运行，生产构建成功。
- PC 和移动端布局正常。
- 不泄露任何密钥、账号密码或内部服务敏感信息。
