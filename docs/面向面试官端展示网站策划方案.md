# 知库 AI 面向面试官端展示网站策划方案

> 日期：2026-11-01  
> 输入：`docs/面向面试官端设计书.md`、项目源码、架构、测试、评估、安全与验收文档  
> 结论：保留原设计目标，将信息组织为“问题 -> 方案 -> 证据 -> 边界”的技术案例页。  
> 实施状态：已并入现有 `frontend/`，公开根路由 `/` 展示项目案例；登录与业务路由保持不变。  
> 源码位置：`frontend/src/showcase/`，独立 `showcase/` 原型不再作为交付源。

## 1. 设计理解

### 1.1 网站本质

面向面试官的项目展示站，不是知识库后台、不是个人简历、不是营销落地页。  
核心任务是在 30 秒内说明项目价值，在 5 分钟内说明技术结构，在 10 分钟内提供可深入查看的实现证据。

### 1.2 原设计优点

1. 目标明确：只服务招聘与技术面试场景。
2. 页面覆盖完整：背景、技术栈、功能、架构、原理、质量、测试、演示、个人贡献齐全。
3. 真实性约束强：禁止虚构功能、指标、链接和贡献范围。
4. 交互要求具体：架构节点、流程步骤、代码复制和配置链接都有明确用途。
5. 明确与业务系统分离，避免展示站影响生产后台。

### 1.3 需要调整的问题

| 原设计风险 | 策划调整 |
|---|---|
| 10 个模块平铺，页面容易变成长技术清单 | 重组为 9 个一级章节，技术细节用标签页、展开面板和抽屉递进展示 |
| 深色科技风容易落入通用 AI 官网模板 | 以真实产品截图、真实架构和证据数据承担视觉主体，渐变只做局部强调 |
| 指标容易被误读为生产准确率 | 指标必须带测量日期、样本条件、Embedding、模型与“演示级评估”限定 |
| 架构图、流程图在小屏幕容易不可读 | 桌面使用可点击关系图，移动端改为按服务排序的纵向流程和折叠说明 |
| 当前部署、备份、干净环境验收未完成 | 使用“已验证 / 已实现待验证 / 未覆盖”状态，不把待验证项写成通过 |
| 在线体验和源码链接尚未配置 | 链接统一配置；无 URL 时不渲染可点击按钮，只显示“待公开”状态 |
| 原业务前端已有 940.67 kB vendor chunk 警告 | 展示站不使用 Element Plus，采用轻量原生 Vue 组件与按需图标 |

## 2. 项目现状审计

### 2.1 可作为展示依据的资产

| 资产 | 当前事实 | 展示用途 |
|---|---|---|
| 业务系统 | Vue 3、Spring Boot 4.1、FastAPI、MySQL 8.4、Redis 8、Qdrant 1.20、Nginx | Hero、技术栈、功能、架构 |
| 业务页面 | 登录、工作台、知识库列表、知识库详情、文档详情、智能问答、系统设置 | 真实界面截图 |
| 权限体系 | JWT、`token_version`、系统角色、知识库 Owner/MANAGER/EDITOR/VIEWER | 权限专题 |
| 文档链路 | 上传、异步任务、TXT/MD/PDF/DOCX 解析、分片、Embedding、Qdrant 索引 | 核心流程 |
| RAG 链路 | 服务端授权过滤、检索、上下文组装、答案生成、引用落库、引用二次鉴权 | 核心流程 |
| 可靠性与安全 | 原子认领、超时回收、幂等、删除补偿、内部 Token、AES-GCM、SSRF 防护、审计 | 工程质量 |
| 自动化结果 | Java 64 项（7 项环境依赖跳过）、Python 85 项、权限矩阵 141 次组合、HTTP 冒烟 20/20 | 测试证据 |
| RAG 评估 | 25 题固定集，Recall@5 97.50%，引用正确率 100%，P95 1973 ms | 评估证据 |
| 文档体系 | 架构、数据库、API、安全、用户手册、运维、排障、验收、已知问题 | 深度阅读入口 |

### 2.2 上线前必须补齐的素材

1. 当前仓库没有公开远程地址，不能生成真实源码链接。
2. 当前没有公开在线演示地址，不能生成“在线体验”可点击按钮。
3. 仓库内没有已整理的展示截图，需要从真实业务系统采集并脱敏。
4. 仓库历史显示单一作者，但“独立开发”或“本人负责范围”仍需项目所有者最终确认。
5. 演示视频此前按用户要求取消，网站不得宣称已有视频。
6. Docker 跨容器 IT、备份恢复演练、干净环境启动仍未执行，不能标记为通过。
7. RAG 使用 `local-hash-v1` Embedding，展示指标必须同时展示这一限制。

## 3. 产品策略

### 3.1 核心定位

一句话定位：  
**知库 AI 是一个带服务端权限边界、可追溯引用和异步索引恢复能力的企业知识库 RAG 平台。**

面向面试官的价值主张不是“用了很多技术”，而是：

- 能设计业务后端与 AI 服务的清晰边界。
- 能把权限落实在检索前，而不是只做页面隐藏。
- 能处理文档索引的状态机、失败重试与数据一致性。
- 能用固定评估集说明效果，也能说明指标边界。

### 3.2 三层阅读节奏

| 阅读层 | 目标时长 | 用户看到的内容 |
|---|---:|---|
| 首屏判断 | 30 秒 | 产品定位、真实界面、技术栈、关键能力、架构入口 |
| 技术概览 | 5 分钟 | 架构、功能闭环、权限、RAG、测试结果 |
| 深度核验 | 10 分钟 | 架构节点职责、流程展开、代码片段、指标条件、贡献与取舍 |

### 3.3 内容组织原则

1. 先给结论，再给实现。
2. 先给证据，再给数字。
3. 先给主链路，再展示扩展模块。
4. 独特实现优先，CRUD 清单降级。
5. 清楚说明边界，不掩饰未验证项。
6. 所有数字必须能回链到项目文档或测试结果。

### 4.1 首屏文案

- 主标题：`知库 AI / KnowBase AI`
- 副标题：`企业级智能知识库与 RAG 问答平台`
- 说明：`从文档解析、异步索引到权限过滤、流式回答与引用追溯，构建一条可解释、可验证的知识问答链路。`
- 技术标签：`Vue 3`、`Spring Boot 4.1`、`FastAPI`、`MySQL 8.4`、`Redis 8`、`Qdrant 1.20`
- 主要按钮：`查看技术架构`
- 条件按钮：`在线体验`、`查看源码`；无 URL 时显示静态“待公开”状态，不渲染空链接

首屏背景使用真实产品界面截图，不使用抽象插画、光球或生成式科技背景。  
文本保持在截图遮罩之外或弱纹理区域，不把整段 Hero 文案放进卡片。

### 4.2 工程证据条

建议展示 4 项：

| 数字 | 文案 | 必带限定 |
|---|---|---|
| 141 | 权限接口/角色组合 | 47 个接口用例 × 3 角色 |
| 85 | Python 测试通过 | 当前环境实际执行 |
| 25 | RAG 固定评估题 | 10 份短文档、演示级评估 |
| 17 | MySQL 业务表 | Flyway 当前模型 |

证据条数字悬停或点击后显示日期、环境和来源链接，避免只看数字产生误解。

### 4.3 架构章节

架构图只表达真实关系：

```text
Browser -> Nginx
Nginx -> Vue 静态资源 + Spring Boot 业务 API
Spring Boot -> MySQL / Redis / 上传卷 / FastAPI
FastAPI -> Qdrant / 外部模型 API
Spring Boot -> 健康检查 FastAPI 与 Qdrant
```

节点说明必须明确：

- Java 是用户、权限、文档、会话、引用和审计的唯一权威源。
- Python 不解析 JWT、不查用户表、不做权限判断。
- Python 只接收 Java 已授权的 `kb_ids`。
- Nginx 不代理 `/internal/**`。
- 生产环境只暴露 80/443。

桌面端节点可点击，点击后显示职责、输入、输出、持久化和安全边界。  
移动端不压缩原图，改为按调用顺序展示节点和连接说明。

### 4.4 核心功能分组

| 分组 | 功能 | 面试重点 |
|---|---|---|
| 身份与治理 | 登录、JWT、`token_version`、角色、知识库成员、审计 | 即时撤销与资源级授权 |
| 知识生命周期 | 建库、成员、上传、解析、分片、索引、重试、删除补偿 | 异步状态机与一致性 |
| RAG 问答 | 检索、上下文组装、SSE、引用、无答案降级、会话历史 | 授权前置与引用可信 |
| 管理与运维 | 模型配置、连接测试、调用日志、健康检查、积压统计 | 密钥保护、SSRF 与可观测性 |

每个功能项包含：

- 一句业务价值。
- 两到三条实现事实。
- 一张真实截图或一个可视流程。
- 对应技术标签。

### 4.5 技术专题

设置 5 个独立专题，不把所有内容堆成一个长流程图：

1. 文档处理与向量索引。
2. RAG 检索、上下文与引用校验。
3. SSE 流式回答与取消。
4. 知识库权限过滤与二次鉴权。
5. 异步任务失败恢复、幂等与删除竞态。

每个专题统一结构：

```text
问题 -> 设计 -> 关键步骤 -> 代码证据 -> 取舍与边界
```

代码片段只展示 8 到 20 行关键逻辑，支持复制。完整代码通过源码仓库入口查看。

### 4.6 个人贡献与取舍

本区不写泛化自我评价，只展示可追问的技术贡献：

1. 负责范围：待本人确认后，按业务后端、AI 服务、前端、测试、部署拆分。
2. 架构决策：为什么采用 Java 业务权威源与 Python AI 计算服务。
3. 权限决策：为什么在检索前计算可读知识库，并对引用再次鉴权。
4. 状态机决策：为什么采用任务表、条件更新、幂等写入和删除补偿，而不是引入 MQ。
5. 可观测性决策：为什么健康检查只返回稳定状态码，并通过 Trace ID 关联日志。
6. 取舍与不足：单机部署、`local-hash-v1` Embedding、无 OCR、无高可用和并发容量基线。

每项采用“背景 -> 选择 -> 证据 -> 代价 -> 后续改进”的固定结构，控制在 80 到 150 字。

## 5. 视觉设计

### 5.1 视觉方向

关键词：`精密`、`可信`、`工程师作品`、`产品质感`。  
避免：大面积紫蓝渐变、漂浮卡片、装饰性光球、无意义粒子、过量圆角、通用 AI 机器人插画。

### 5.2 色彩

| 用途 | 建议色 |
|---|---|
| 页面底色 | `#071018` |
| 次级表面 | `#0D1724` |
| 主文本 | `#E8EEF7` |
| 次文本 | `#9BAABD` |
| 主强调 | `#4D8DFF` |
| 次强调 | `#48C7D9` |
| 克制紫强调 | `#8B7CF6` |
| 已验证 | `#52D3A2` |
| 待验证 | `#F5B84B` |
| 未覆盖/风险 | `#FF6B6B` |

蓝紫渐变只用于细线、焦点、进度和少量标题光感。  
证明类区域使用青色、绿色和琥珀色区分状态，避免整页只有蓝色一种色相。

### 5.3 版式与材质

- 页面最大内容宽度 `1200px` 到 `1320px`。
- 使用 8px 间距体系。
- 功能卡和面板圆角不超过 `8px`。
- 背景使用低对比网格、细边框和分区色带，不使用大面积发光。
- 标题保持紧凑层级，Hero 之外不重复超大字号。
- 英文指标可使用等宽字体；中文正文使用系统中文字体。
- 图标使用 `lucide-vue-next`，不使用手绘装饰图标替代真实语义。

### 5.4 真实视觉资产

需要从业务系统采集以下截图：

1. 工作台。
2. 知识库文档处理页。
3. 文档分片详情。
4. RAG 流式回答与引用。
5. 模型配置或健康检查。
6. 权限不足页或审计页面。

采集规范：

- 使用固定演示数据，不出现真实密钥、个人信息、Cookie、终端和内部域名。
- 桌面截图使用 `1440 × 900` 或更高分辨率。
- 同步采集 `390px` 宽移动截图，验证真实响应式。
- 统一主题、缩放和浏览器边框。
- 输出 WebP 或 AVIF，保留原图到非构建目录。
- 不用生成图伪造系统界面。

## 6. 技术方案

### 6.1 技术选型

| 项 | 方案 | 理由 |
|---|---|---|
| 应用位置 | `frontend/src/showcase/` | 复用现有前端构建、部署与路由，避免双份源码漂移 |
| 框架 | Vue 3 + TypeScript + Vite | 与现有技术栈一致，静态构建简单 |
| 路由 | 根路由 `/` + 页内锚点 | 面试阅读路径连续；`/login` 与业务后台独立 |
| UI 库 | 不使用 Element Plus | 避免后台感与既有大包体问题 |
| 图标 | `lucide-vue-next` | 语义图标、按需引入 |
| 动效 | CSS + IntersectionObserver | 减少运行时依赖 |
| 图表 | 轻量 HTML/CSS/SVG | 指标展示简单，无重型图表库 |
| 测试 | Playwright + 内容校验脚本 | 覆盖展示页、登录入口、未知路由与响应式 |

### 6.3 内容类型

所有内容集中配置并带状态：

```ts
type EvidenceStatus = 'verified' | 'implemented' | 'pending' | 'not-covered'

interface EvidenceMetric {
  label: string
  value: string
  conditions: string
  measuredAt?: string
  source: string
  status: EvidenceStatus
}
```

架构节点至少包含：

```ts
interface ArchitectureNode {
  id: string
  name: string
  group: 'entry' | 'application' | 'ai' | 'data' | 'external'
  responsibility: string
  inputs: string[]
  outputs: string[]
  securityBoundary?: string
}
```

外部链接统一管理：

```ts
type LinkState =
  | { state: 'live'; url: string }
  | { state: 'pending'; note: string }

interface ExternalLinks {
  demo?: LinkState
  source?: LinkState
  readme?: LinkState
  runbook?: LinkState
}
```

组件只对 `state: 'live'` 渲染可点击按钮。  
未配置时显示状态文本，不生成 `href="#"` 或空按钮。

### 6.4 核心组件

- `SiteHeader`：桌面锚点导航、移动抽屉、滚动进度。
- `HeroSection`：项目定位、真实截图、技术标签、有效 CTA。
- `EvidenceStrip`：关键数字与条件说明。
- `ContextSection`：问题与解决方式。
- `ArchitectureCanvas`：节点、连线、职责抽屉。
- `TechStackGrid`：按前端、Java、AI、数据、部署分组。
- `CapabilityTabs`：功能分组和真实截图。
- `WorkflowExplorer`：五类技术流程逐步展开。
- `EvidenceDashboard`：测试、评估、状态和限制。
- `ContributionSection`：本人范围、决策、难点、取舍。
- `DemoSection`：有效外链、演示说明和推荐问题。
- `SiteFooter`：文档入口、技术栈、更新时间。

### 6.5 交互与可访问性

- 锚点跳转使用 `scroll-behavior: smooth`，并兼容 `prefers-reduced-motion`。
- 使用 IntersectionObserver 更新当前导航项。
- 所有可点击架构节点同时支持键盘 Enter/Space。
- 截图放大使用可关闭的模态层，支持 Esc、焦点锁定和返回触发按钮。
- 代码复制按钮显示成功状态，并保留可访问文本。
- 状态不能只靠颜色区分，必须同时有文字和图标。
- 移动菜单关闭后焦点返回菜单按钮。
- 页面不出现横向滚动、文字裁切和固定层遮挡。

## 10. 部署方案

展示站是纯静态应用，推荐使用独立子域名或独立静态容器。

### 10.1 配置项

```env
VITE_SHOWCASE_BASE=/
VITE_DEMO_URL=
VITE_SOURCE_URL=
VITE_README_URL=
VITE_RUNBOOK_URL=
```

空 URL 在构建时转换为 `pending` 状态。  
真实生产环境变量不得提交到仓库。

### 10.2 部署边界

- Nginx 只提供静态文件与 SPA/锚点回退。
- 展示站不代理 `/internal/**`。
- 展示站不读取业务系统 JWT。
- 展示站不调用管理接口获取项目数据。
- 展示页使用现有前端根路径 `/`，构建产物与业务后台共用 `frontend/dist/`。
- 部署文档补充缓存、gzip/brotli、CSP、安全响应头和回滚步骤。

### 10.3 上线后检查

- 首页、锚点和所有按钮可访问。
- 移动菜单和外部链接正常。
- 图片尺寸和缓存策略正常。
- 页面源代码不包含内部地址、密钥和测试密码。
- 指标条件与最新验收报告一致。
- 页面“最后更新日期”已更新。

## 11. 风险与控制

| 风险 | 信号 | 控制 |
|---|---|---|
| 页面变成功能清单 | 首屏阅读后仍不知道项目亮点 | 首屏只保留定位、截图、三个入口和一个证据条 |
| 视觉同质化 | 看起来像通用 AI 模板 | 真实业务截图、真实架构、克制渐变、工程证据优先 |
| 指标被误读 | 页面只显示 97.50% | 数字与条件、日期、来源、限制绑定显示 |
| 架构与代码不一致 | 节点职责和实际服务不同 | 以 `ARCHITECTURE.md` 和代码为准，发布前交叉核对 |
| 缺失链接造成死按钮 | 空 `href` 或点击无反应 | 统一 `LinkState`，无有效 URL 不渲染按钮 |
| 截图泄露信息 | 出现账号、密钥、内部域名 | 固定演示数据，采集后人工检查，原图不进构建 |
| 移动端架构图不可读 | 缩小后文字低于可读尺寸 | 桌面图和移动流程分开实现 |
| Docker 未验收削弱可信度 | 访客以为全部通过 | 明确标注“配置解析通过，运行时验收待执行” |
| 作品范围表述不实 | 面试追问无法证明 | 发布前由本人确认贡献边界，并附可核验证据 |
| 内容快速过期 | 指标和状态与仓库不一致 | 建立 `lastReviewedAt`，每次测试报告更新后同步内容 |
