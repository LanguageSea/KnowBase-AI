# 知库 AI 项目展示网站与在线演示系统安全加固要求

## 1. 总体目标

为面向公众访问的知库 AI 项目展示网站建立合理的纵深防御，尽量降低常见 Web 攻击、未授权访问、敏感数据泄露、资源耗尽、AI API 费用滥用及服务器被入侵的风险。

安全要求适用于：
- 项目展示网站。
- 在线演示前端。
- Spring Boot 业务后端。
- FastAPI AI 服务。
- MySQL、Redis、Qdrant 和文件存储。
- Docker Compose、Nginx 及 Linux 服务器部署环境。

不能宣称系统绝对安全。所有安全措施必须有实际配置、代码实现或测试证据。

## 2. 开始修改前

先检查现有代码、项目结构、接口、认证方式、Docker Compose、Nginx 配置、环境变量和部署文档。

首先输出：
1. 当前系统的信任边界和公开入口。
2. 已有安全措施及其代码位置。
3. 潜在风险清单，按严重程度排序。
4. 推荐修改方案及可能影响的正常功能。
5. 每项风险的验证方式。

不得在没有检查现有实现前，直接假设某项安全措施已经存在。

## 3. 网络与部署隔离

- 将公开展示站与在线演示业务系统分开部署或分开访问入口。
- 展示站尽可能使用静态资源，不暴露不必要的业务接口。
- 所有公网流量经过 Nginx 或可信的受控入口。
- 生产环境启用 HTTPS。
- MySQL、Redis、Qdrant、FastAPI 内部接口不直接暴露公网。
- 仅开放必要的公网端口。
- Docker 容器使用最小权限，避免 privileged 和不必要的宿主机挂载。
- 为生产环境建立独立配置，开发环境和生产环境不能共用真实密钥。
- 提供明确的端口映射、网络拓扑和服务访问清单。

## 4. Nginx 和 HTTP 安全

配置并验证：
- HTTP 到 HTTPS 的跳转。
- Content-Security-Policy。
- X-Content-Type-Options: nosniff。
- Referrer-Policy。
- 合适的 frame-ancestors 或 X-Frame-Options。
- 合适的 HSTS 配置，仅在 HTTPS 部署和域名条件满足后启用。
- 登录、问答、上传和模型测试等接口的独立限流。
- 请求体大小限制、连接超时、上游超时和并发控制。
- 对敏感响应使用合适的 Cache-Control。
- 生产环境不输出调试堆栈和内部服务信息。

CSP 必须根据实际使用的脚本、样式、字体、图片和 API 来源配置，禁止为方便而长期使用过度宽松的策略。

限流不能只依赖单个 IP；需要考虑共享出口、反向代理、账号和业务预算等因素。

## 5. Web 应用安全

检查并处理：
- SQL 注入：使用参数化查询，禁止不安全的字符串拼接。
- XSS：正确输出编码，不直接渲染未经清理的用户 HTML。
- CSRF：根据 Cookie 或 Bearer Token 认证模式实施对应措施。
- CORS：仅允许明确的可信来源。
- 身份认证：验证 Token 的签名、有效期和必要的声明。
- 授权：服务端对每个敏感资源进行对象级权限校验。
- 登录保护：失败限速、异常登录记录及合理的错误信息。
- 参数校验：限制长度、类型、范围和允许值。
- 错误处理：不返回堆栈、密钥、SQL 或服务器内部路径。
- 依赖安全：检查过期依赖、已知漏洞和不安全的版本组合。
- 敏感信息：不得将密码、Token、模型密钥写入前端代码或日志。

不要仅通过前端隐藏按钮实现权限控制。

## 6. 文件上传和文档解析

- 对允许的文件类型建立服务端白名单。
- 校验文件实际内容，不仅依赖扩展名或客户端 MIME 类型。
- 限制单文件大小、页数、解压后体积和解析时间。
- 使用随机文件名，防止路径穿越和文件覆盖。
- 将上传文件存放在 Web 根目录之外。
- 禁止直接执行或直接作为可信 HTML 渲染上传文件。
- 为文档解析任务设置资源上限和超时。
- 处理重复上传、任务失败、删除文档和向量索引清理。
- 根据需要采用隔离进程或容器执行高风险解析工作。

## 7. RAG 与 AI 专项安全

- 模型 API Key 只存储在服务端，必要时使用经过审查的加密存储方案。
- 限制模型调用频率、Token 消耗、输出长度、并发和总预算。
- 记录调用统计，但不记录明文密钥和不必要的敏感提示词。
- 将检索文档视为不可信输入，防范提示词注入。
- 不允许模型决定用户的数据访问权限。
- 在检索前通过服务端权限过滤知识库范围。
- 在返回引用、文档片段和下载链接时再次验证资源权限。
- 模型工具调用必须经过服务端允许名单、参数校验和权限校验。
- 如果模型服务允许配置 base_url，防范 SSRF、内网探测、云元数据访问和不安全重定向。
- 对模型调用超时、错误重试和服务不可用建立上限与降级策略。
- 演示环境仅使用专门的虚构数据，不暴露真实私人或企业数据。

## 8. 服务间通信与数据保护

- FastAPI 内部接口要求可信的服务间认证。
- 服务凭证通过环境变量或安全配置注入，不硬编码在代码仓库。
- 对关键内部操作验证调用身份、参数和允许执行的操作。
- 数据库采用独立的最小权限账户。
- 禁止将数据库、Redis、Qdrant 端口直接映射到公网。
- 日志对密码、Token、API Key、Cookie 和其他敏感信息进行脱敏。
- 对备份文件和上传文件设置合理的访问权限。
- 提供备份恢复流程，并验证恢复后数据可用性。

## 9. 服务器安全与运行维护

- 使用 SSH 密钥认证，限制管理入口和不必要的端口。
- 及时安装操作系统、容器基础镜像和应用依赖的安全更新。
- 使用非 root 用户运行应用容器。
- 限制容器 CPU、内存、进程数及文件系统访问。
- 设置磁盘空间和异常资源消耗监控。
- 为异常请求、认证失败、限流触发、服务异常和模型预算耗尽建立日志或告警。
- 准备故障处理、密钥轮换、服务恢复和数据恢复步骤。
- 不在公开页面展示真实服务器 IP、管理地址、内部拓扑细节、敏感日志或生产配置。

## 10. 安全测试

在授权的本地测试环境中验证：
- 未登录访问受保护接口时被拒绝。
- 普通演示用户不能执行管理员操作。
- 用户无法通过修改 ID 访问其他用户的文档和引用。
- 非法文件、超大文件、路径穿越文件名被拒绝。
- 超出请求频率或模型预算后请求受到限制。
- 错误输入不能造成 SQL 注入或 XSS。
- CORS 不允许未经授权的来源。
- FastAPI 内部接口不能被未授权调用。
- 模型 URL 配置不能访问受保护的内网地址。
- 异常请求不会泄露密钥、堆栈或内部路径。
- 容器、数据库端口和管理接口不存在不必要的公网暴露。
- 数据备份能够成功恢复。

不得对未授权的第三方网站、服务器或网络进行攻击测试。

## 11. 交付物

请输出：
1. 安全风险清单。
2. 已实施的代码与配置变更。
3. Nginx 和 Docker Compose 安全配置。
4. 环境变量模板，不含任何真实密钥。
5. 安全测试用例、实际执行结果和未通过项。
6. 生产上线前检查清单。
7. 剩余风险及后续改进建议。

对于无法在当前环境验证的项目，明确标注“未验证”，不得声称已经通过安全测试。

先完成高风险问题和基础防护，再逐步完善其他项目；每次修改后运行对应测试，确保安全改动不破坏现有功能。
