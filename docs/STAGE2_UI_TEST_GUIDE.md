# Stage 2 图形界面测试指南

> 适用于 `SPRING_PROFILES_ACTIVE=dev`。开发环境会额外加载 `db/dev/R__zz_dev_test_users.sql`，
> 默认测试账号不会写入生产环境。

## 1. 启动后登录

打开 `http://127.0.0.1:5173/login`。若 5173 已被其他程序占用，Vite 会顺延到
`http://127.0.0.1:5174/login`；以终端输出的地址为准。开发模式下登录页会显示“测试账号”快捷入口。

| 账号 | 密码 | 系统角色 | 测试用途 |
|---|---|---|---|
| `admin` | `Admin@123456` | `SYS_ADMIN` | 系统用户、角色和全部知识库管理 |
| `kbadmin` | `Test@123456` | `KB_ADMIN`、`USER` | 创建知识库并管理自有库 |
| `editor` | `Test@123456` | `USER` | 被授权后测试上传、删除和重试 |
| `viewer` | `Test@123456` | `USER` | 被授权后测试只读、预览和下载 |

## 2. 用户与角色管理

1. 使用 `admin` 登录，点击顶部“用户与角色”；管理页面地址为 `/system/users`，支持刷新和直达。
2. 新建用户，填写用户名、初始密码、昵称和角色。
3. 在角色列点击“配置”，调整 `SYS_ADMIN`、`KB_ADMIN`、`USER`。
4. 点击“重置密码”，确认该用户旧会话立即失效。
5. 切换启禁用状态，确认禁用后用户无法继续使用旧 token。
6. 尝试禁用当前 `admin` 或移除最后一个 `SYS_ADMIN`，应出现冲突提示。

## 3. 知识库与成员权限

1. 使用 `admin` 或 `kbadmin` 新建知识库。
2. 在知识库列表点击“成员权限”，进入“成员权限”标签。
3. 搜索并添加 `editor`，角色选择 `EDITOR`。
4. 搜索并添加 `viewer`，角色选择 `VIEWER`。
5. 修改成员角色或移除成员，确认列表立即反映变化。
6. 用 `viewer` 登录：可查看知识库和文档，但看不到上传、删除、重试和成员配置操作。
7. 用 `editor` 登录：可上传、删除和重试文档，但不能配置成员。

## 4. 文档处理

1. 进入知识库详情的“文档处理”标签。
2. 使用“上传文档”选择 TXT、MD、PDF 或 DOCX，单文件不超过 20 MB。
3. 上传后观察状态自动刷新：
   `PENDING → PROCESSING → ACTIVE`。
4. 重复上传相同文件，应返回 409。
5. 上传扫描版 PDF，应显示 `NO_TEXT_LAYER` 和可读错误信息。
6. 失败文档在未达到尝试上限时显示“重试”；达到上限后不显示重试。
7. 删除文档后观察 `DELETING`；成功后文档从列表消失，Qdrant 对应 point 归零。

## 5. 文档查询

1. 在“文档处理”标签使用关键词搜索文档名或错误信息。
2. 使用状态下拉框筛选排队、处理、可用和失败文档。
3. 点击文档名进入详情页，查看格式、大小、分片数量、尝试次数和错误摘要。
4. 在分片预览中翻页查看 `seq`、页码、标题和内容。
5. 点击“下载原文件”，确认浏览器保存原始文件。
6. 使用未获授权账号直接访问文档 URL，应返回 403。

## 6. 自动刷新

知识库详情和文档详情每 2 秒轮询未终态文档。处于 `PENDING`、`PROCESSING`、`DELETING` 时无需手动刷新；
文档进入 `ACTIVE`、`FAILED`、`DELETED` 或 `DELETE_FAILED` 后停止高频轮询。
